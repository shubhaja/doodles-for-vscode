Configurable weather background

The settings dropdown includes an editable Weather & time location field, empty until a location is selected. Add the city/country, click Find location (or press Enter), then choose a result. Searches go to Photon / OpenStreetMap only when submitted; weather requests send only the selected coordinates to Open-Meteo. Selection immediately exits weather previews, refreshes conditions, and persists in local browser storage. Failed searches leave the active location unchanged. Until selection, existing configured coordinates (default: Koreatown NYC) remain active and are shown beneath the field. Changing extension coordinate settings starts a separate saved-location preference.


Open-Meteo (https://open-meteo.com/en/docs, CC BY 4.0) current modeled cloud_cover, weather_code, is_day, rain, showers, wind_speed_10m, and wind_gusts_10m at 40.7479,-73.9867. Fetches on startup, every 5 minutes, on focus/visibility return and reconnection (30-second request debounce). Current conditions have 15-minute time steps. Rain plus showers are normalized using current.interval to mm/hour; wind is explicitly requested in km/hour. Fresh cache is retained during outages; effects disappear after two hours of stale data.

Rain density now follows liquid rainfall with a visual curve capped at 100% at 10 mm/hour. Dry and snowy weather codes do not generate rain. Missing rainfall fields fall back to the previous code-based 25/60/100% amounts. Wind/gust speed controls the fine-rain gust dial from 0–100% (60 km/hour reaches 100%). Missing wind data and manual previews use the selected 19% gusts. The rain preview starts at the selected 100% density; live weather restores the current density and wind when the preview ends.

Drizzle, rain, showers, and thunderstorms produce gentle, click-through rain. A fresh transition from rain to clear or mainly clear daytime skies shows a faint rainbow for 90 seconds, with a soft fade. Repeated sunny updates do not replay it; night, overcast conditions, and stale observations do not trigger it. Reduced motion uses stationary raindrops. Hidden windows pause the animations.

Sun, cloud, rain, and rainbow buttons sit beside the eye in the top-right toolbar. Each previews that effect for 90 seconds; click the active button again to return early. Live weather continues updating during previews. When a preview ends, the latest fresh weather is restored (including rain or clouds after a rainbow); unavailable or stale weather hides the effects. Previews never overwrite the weather cache.

The injected weather block bundles vendor/simplex-noise.js, cloud-field.js, fine-rain.js, rain-field.js, and ktown-weather.js in that order. The portable extension build bundles the same files. No CDN is needed at runtime. simplex-noise 4.0.3 by Jonas Wagner is MIT licensed; see vendor/LICENSE.simplex-noise and https://github.com/jwagner/simplex-noise.js/. The vendored browser wrapper contains the upstream CommonJS source unchanged inside a local exports scope.

Clouds are a five-octave evolving simplex-noise field. Cloud cover lowers the density threshold so patches grow and merge into overcast; this is a procedural visual simulation, not an atmospheric physics model. A capped-resolution canvas updates at most six times per second, pauses when hidden, and stays still under reduced motion. It covers the full viewport under the grass (weather z-index 990, grass 1000). Alpha stays below 30% to preserve text readability. Rain uses the shared native Canvas renderer in fine-rain.js, with the selected recipe: speed 470 px/s, streak length 8 px, width 1.2 px, opacity 44%, wind angle -8 degrees, depth variation 100%, density up to 100%, and fallback gusts 19%. rain-field.js supplies the viewport lifecycle and live density/gust controls. The overlay adds no extra opacity reduction. Rain caps at 1,800 drops and 2x pixel ratio, pauses while hidden, freezes for reduced motion, and preserves drop positions when settings change. The apply script and portable build bundle fine-rain.js before rain-field.js..

Night colors interpolate through soft red (#e8a5aa) at midnight, eerie pastel lime green (#b9edaa) at 3am, and purple (#c6ade6) at 4am. The native and portable extensions use the same stops.

In the patched workbench, the settings slider calls Daylight Sky through the native command service exposed by the terminal integration. Daylight Sky owns the selected time and updates workbench.colorCustomizations, including terminal.background. The slider reads that same state; selecting live time clears the override. The CSS/xterm palette is only a standalone-preview fallback and is released when the native bridge becomes available. Applying updates the installed Daylight Sky extension and bridge together; reload activates them. Explicit application cell backgrounds remain controlled by the application, and the old pre-open transparency hook remains retired.

neutral-focus-dim.css uses a light multiply tint derived from the live editor background (35% sky color mixed with white) for unfocused terminal panes. This gently darkens the current sky hue and follows theme updates automatically. Daylight Sky begins sunset at 17:00 and reaches pastel coral pink at 18:00. Reload Window applies these changes.

The selected location also controls the live time slider and sky colors. Open-Meteo resolves the time zone from coordinates; the saved zone keeps the clock working offline and accounts for daylight saving changes. Selecting a location exits time previews. Until its time zone is available, settings explicitly show that device time is being used.
